# Discord Incoming Webhook受入計画

## 目的

状態イベントから生成された安全な通知が、専用DiscordチャンネルへIncoming Webhookで
配送されることを確認します。Discord障害や配送遅延が、Minecraftの安全切断、終了理由、
終了コードを変えないことも確認します。

この文書は試験計画です。実Webhook URL、チャンネルID、Minecraft接続先、BOT名、
プレイヤー名、認証情報は記録しません。

## 承認ゲート

試験開始前に、次を個別に承認します。

- 専用Discordチャンネルへの実送信
- Webhook URLの実行環境への一時的な注入
- 専用Minecraftテストサーバーへの接続
- runtime用Dockerサービスまたはコンテナの起動
- 他プレイヤー検知試験を行う場合の実機プレイヤー参加

Webhook URLをチャット、コマンド履歴、ログ、試験記録へ表示しません。`.env`の内容を
表示・変更せず、既存の認証volumeを削除、初期化、再作成しません。

## 事前条件

- 対象commit、ブランチ、作業ツリーが確認済みである
- format、型、lint、全自動テスト、build、Compose検証が成功している
- 専用Discordチャンネルに試験用Webhookが用意されている
- 専用Minecraftテストサーバーの使用許可がある
- runtimeとsmokeを含む競合コンテナが動作していない
- 通知本文と構造化ログに秘密情報が含まれないことを自動テストで確認済みである

## 試験1: 接続ライフサイクル通知

1. 通知を有効にしたruntimeだけを起動します。
2. BOT以外のプレイヤーを参加させず、接続とspawnを完了させます。
3. 専用Discordチャンネルで、接続開始、login完了、spawn完了に対応する通知を確認します。
4. 各通知が1件だけで、revision順に並ぶことを確認します。
5. `@everyone`、`@here`、ユーザーmentionが発生しないことを確認します。
6. Webhook URL、Minecraft接続先、BOT名、プレイヤー名、生Errorが本文にないことを確認します。

合格条件は、runtimeが読み取り専用接続を維持したまま、対象通知を重複なく安全な本文で
配送することです。

## 試験2: SIGTERMと配送の隔離

1. 接続・spawn完了後にruntimeへSIGTERMを送ります。
2. Minecraftの切断とruntime終了がDiscord配送完了を待たず進むことを確認します。
3. `reason: "signal_sigterm"`、`outcome: "normal"`、`exitCode: 0`を確認します。
4. runtimeコンテナが停止し、再接続しないことを確認します。
5. 停止要求・正常停止通知の配送有無を記録します。

現在は永続outboxを持たず、runtime終了時に未完了配送をAbortするため、停止直前通知は
best effortです。停止通知が未配送でもMinecraftの安全終了を優先します。停止通知の
永続保証はMySQL等のoutbox導入時に別の受入条件として追加します。

## 試験3: 他プレイヤー検知と安全停止

この試験は実機プレイヤー参加の追加承認後だけ実施します。

1. BOT単独で接続・spawn完了まで待機します。
2. プロジェクト所有者の合図後に実機プレイヤーを参加させます。
3. 他プレイヤー検知が1回だけ処理されることを確認します。
4. Minecraftが直ちに安全切断し、再接続しないことを確認します。
5. `reason: "other_player_detected"`、`outcome: "normal"`、`exitCode: 0`を確認します。
6. 緊急停止通知が配送された場合、プレイヤー名を含まない固定本文であることを確認します。

安全切断と終了コードが必須の合格条件です。緊急停止通知は現段階ではbest effortであり、
配送成否によって安全切断を遅延または失敗させてはいけません。

## 失敗時の停止条件

次を確認した場合、再試験や自動修正をせずruntimeを安全停止して報告します。

- 通知本文またはログへの秘密情報、接続先、個人情報の混入
- mentionの発生
- 通知待機によるMinecraft切断の遅延または失敗
- 他プレイヤー検知後の再接続
- 重複したMinecraft接続またはDiscord通知の無制限反復
- 意図しないMinecraft内操作
- 対話的な認証や予期しない外部入力の要求

## 非秘密な記録項目

試験後は次だけを`docs/verification/`へ記録します。

- 対象commitと実施日
- 各試験の合否
- 通知type、件数、順序
- mention抑止結果
- 安全切断の結果、終了理由、終了コード
- 再接続と重複配送の有無
- 配送エラー分類と試行回数（発生時）

Webhook URL、チャンネルID、サーバー情報、アカウント名、プレイヤー名、認証情報、
DiscordメッセージIDは記録しません。
